# Tala Interactive native cell benchmark

This is the first ORC-backed Interactive cell lifecycle baseline, refreshed after exact entry-signature validation was
added to ORC module registration. It is measured from the working tree based on `85cd216`; the C++ changes in this tree
were not committed when the measurement was taken.

## Environment

| Field | Value |
| --- | --- |
| OS | Windows build 26200 (Windows 11 family) |
| CPU | Intel Core i5-3210M @ 2.50 GHz; 2 cores / 4 logical processors |
| LLVM / ClangCL | 22.1.8 |
| Bazel | 9.2.0 |
| Build profile | `-c opt` |
| Benchmark library | Google Benchmark, repository-pinned module |
| Date | 2026-09-24 |

## Measured operation

`BenchmarkCellLowerAddInvokeReset` constructs a one-function CorePrep module returning a signed 64-bit constant, lowers it
through the production Xpp and Xmm APIs, lowers Xmm to verified LLVM bitcode, creates a unique ORC resource tracker,
adds and looks up the module, invokes the exact scalar host ABI, and removes the module from the persistent `LLJIT`.
Fixture construction and Google Benchmark reporting are outside the loop; the per-cell IR lowering and resource cleanup
are included.

The case intentionally isolates the C++ native half of a REPL cell. It excludes the Haskell frontend process startup,
temporary source/Core file I/O, terminal work, and time waiting for a human. It is a native JIT throughput baseline, not
end-to-end keystroke latency.

## Result

Command:

```powershell
bazelisk build -c opt //Interactive/Benches:interactive_benches
./bazel-bin/Interactive/Benches/interactive_benches.exe `
  --benchmark_filter="BenchmarkCellLowerAddInvokeReset" `
  --benchmark_min_time=0.1s --benchmark_repetitions=5 `
  --benchmark_report_aggregates_only=true
```

| Aggregate | Wall time / cell | CPU time / cell |
| --- | ---: | ---: |
| Mean | 2.315 ms | 2.276 ms |
| Median | 2.306 ms | 2.315 ms |
| Standard deviation | 0.0995 ms | 0.161 ms |
| Coefficient of variation | 4.30% | 7.09% |

Only five repetitions were requested, so this is a first machine-specific checkpoint, not a statistically strong
cross-version performance claim. Windows scheduling and the old mobile CPU materially influence the spread. Use the same
host and optimized command for a later comparison; do not compare the earlier fastbuild smoke number to this result.

## Interpretation

The full native cell path completed in about 2.3 ms on this host. This confirms the synthetic CorePrep-to-JIT lifecycle is
small enough to benchmark as a single operation, while also showing that verified IR lowering and ORC resource management
are measurable work. End-to-end interactive latency will be higher because this design currently starts the Haskell
frontend process and writes/reads one isolated Core artifact for each cell. Reducing that component requires a supported
long-lived frontend protocol; removing the type checker or bypassing compiler stages is not an optimization target.

The benchmark resets resource trackers on every iteration so repeated measurement has a bounded memory footprint and
models a fresh REPL generation. The REPL itself retains each successful cell until `:reset`, allowing the session to own
all generated symbols and release them together at the explicit lifecycle boundary.
